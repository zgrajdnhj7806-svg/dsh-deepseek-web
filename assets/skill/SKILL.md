# DeepSeek 网页版（deepseek-web）

这个技能把 DSH 接到**你自己账号的 DeepSeek 网页版**（chat.deepseek.com）上。
它**不是本地模型**：每次调用都是真实的一次网页端对话，走 PoW 挑战 + SSE 流式。

因此它有两条铁律：
- **慢**：通常 5–60 秒才回，复杂问题更久；
- **串行**：网页端账号同一时刻只允许一路流式请求，任何时刻只能有一个调用在线。

> 一句话定位：**当第二模型用，别当主力模型用**。常规工作走 DSH 自己的模型更快更省。

---

## 什么时候用它（用）

- 用户**明确点名**「用 DeepSeek 网页版 / 官网 / 网页端模型 / R1 深度思考」。
- 用户要求「从第 xx 行看到 xx 行分析」，需要**带行号**的精确定位结论。
- 需要**第二意见**：本地模型已给出方案，想让另一个模型独立复核对错。
- 需要网页端特有的能力：深度思考（DeepSeek-R1 风格推理）、联网搜索。
- 需要跨会话的多轮追问（同一 label 复用同一网页端对话，上下文连续）。

## 什么时候不用它（不用）

- 常规问答、写代码、总结——本地模型更快更省。
- 用户没要求、也没暗示要网页端模型时，**默认不要用**。
- 需要**并发**多个请求的场景——网页端做不到，永远串行。
- 内容敏感（含密钥、私密数据）——发给网页端的内容会离开本机。

---

## 三个工具

| 工具 | 定位 | 何时选它 |
|---|---|---|
| `deepseek_web_analyze_lines` | **首选**。读文件第 `start_line`–`end_line` 行，把带行号的代码片段发给网页端模型分析 | 涉及「代码片段 + 行号级结论」的一切请求 |
| `deepseek_web_ask` | 直接提问，不读文件 | 纯问题、要第二意见、深度思考、联网搜索 |
| `deepseek_web_status` | 只读检查登录状态（不发起请求） | 任何 `auth` 报错发生时，或用户可能未登录时 |

**顺序建议**：`analyze_lines` > `ask` ≈ `status`。凡是能带上文件行号的，都优先 `analyze_lines`：
它把代码和行号一起发过去，模型能引用具体行号，结论可核对，这是 `ask` 做不到的。

---

## 工具一：deepseek_web_status（先查状态）

调用 `deepseek_web_ask` / `deepseek_web_analyze_lines` 前，如果**不确定是否登录**（首次使用、
报过错、很久没用），先调它。它是纯本地检查，不产生网页端请求，零成本。

**返回字段**：

| 字段 | 含义 |
|---|---|
| `loggedIn` | 是否保存了 token |
| `tokenPreview` | 脱敏后的 token（如 `abc123…xyz9`），绝不显示明文 |
| `source` | 凭据来源：`credentials-service`（DSH 凭据服务）/ `plugin-file`（插件文件）/ `legacy-file`（只读导入）/ `none` |
| `message` | 人话摘要；未登录时会直接告诉用户去哪登录 |
| `userId` | token 校验成功时的账号 id（空串表示未校验） |

**没登录时的标准处理**：不要替用户登录，也不要把登录失败吞掉。把 `message` 原样告诉用户，
并明确指引：**DSH 设置 → DeepSeek 网页版** 里点「一键登录（打开 Edge）」，或粘贴 token。

## 工具二：deepseek_web_analyze_lines（行区间分析，首选）

### 参数

| 参数 | 必填 | 说明 |
|---|---|---|
| `path` | ✅ | 文件绝对路径 |
| `start_line` | ✅ | 起始行号（1 起，含） |
| `end_line` | 否 | 结束行号（1 起，含）；省略则读到文件末尾 |
| `instruction` | 否 | **本次任务特别要求**，原样追加在提示词末尾并标为「优先满足」。适合收窄输出，如「只列问题和行号，不要重写代码」 |
| `focus` | 否 | 关注点提示，如「错误处理」「并发」「性能」，会写进提示词的关注方向 |
| `thinking` | 否 | 开深度思考（默认跟随插件设置） |
| `fresh` | 否 | 不复用本对话的网页端上下文，强制新会话 |
| `label` | 否 | 会话标签名；同 label 复用同一个网页端会话（多轮） |

### 标准流程（照做）

1. **先用你自己的读取工具确认行号**：核对文件存在、行数，算出 `start_line`/`end_line`，
   不要凭记忆报行号。`end_line` 省略 = 读到末尾。
2. **一次只分析一个区间**。区间过大（默认上限 400 行 / 60k 字符）会被**直接拒绝**——
   拒绝是为了防止把整文件塞进去。大文件请拆成多次调用，一次调一个区间。
3. **调 `analyze_lines`**，按需传 `instruction` / `focus` 收窄输出。
4. **核对返回**：结果带 `startLine` / `endLine` / `totalLines` / `truncated`，确认
   实际分析的行号与预期一致；`truncated: true` 表示按字符上限截断了。

### 示例

```
deepseek_web_analyze_lines({
  path: "C:/proj/src/server.js",
  start_line: 120,
  end_line: 180,
  focus: "错误处理与并发",
  instruction: "只列问题和行号，不要重写代码"
})
```

返回要点：模型会给出**带行号的**分析（因为发过去的代码带行号）。即使模型结论有错，
行号也让你能回查原文复核——这正是它比 `ask` 值钱的地方。

## 工具三：deepseek_web_ask（直接提问）

### 参数

| 参数 | 必填 | 说明 |
|---|---|---|
| `prompt` | ✅ | 问题或指令 |
| `thinking` | 否 | 开深度思考（DeepSeek-R1 风格推理）。默认跟随插件设置 `defaultThinking` |
| `search` | 否 | 开联网搜索。默认跟随插件设置 `defaultSearch` |
| `fresh` | 否 | 开新会话（不加就沿用当前 label 的会话） |
| `label` | 否 | 会话标签；同 label 复用会话保持多轮 |

### 典型用途

- **要第二意见**：把本地模型已给的方案原样贴进 `prompt`，让网页端独立复核。
- **用户点名要 R1/深度思考**：传 `thinking: true`。
- **要最新信息**：传 `search: true` 走联网搜索。

### 示例

```
deepseek_web_ask({
  prompt: "请独立复核这个方案：<本地模型给出的完整方案>。只指出错误和风险，不要重复优点。",
  thinking: true
})
```

---

## 多轮上下文机制（label 与 fresh）

- 每次调用的会话 key = **`本 DSH 会话 id` + `label`**（默认 label 为 `default`）。
- 同一 DSH 对话里、同一个 `label` 的多次调用 → 落到**同一个网页端会话** → 追问是**连续**的（模型记得前面的内容）。
- 要开新话题 / 防上下文串味：**换一个 `label`**，或传 **`fresh: true`**。
- 跨「换 label / fresh 会话」之间互不可见，符合直觉：新会话 = 新上下文。

> 注意默认行为：不加 `fresh` 时，同 label 的追问会带上之前全部上下文。若新一轮问题
> 与旧上下文无关，请主动换 label 或 `fresh: true`，避免旧内容干扰回答。

## 登录（三条路）

网页端用**你自己的账号**，必须先登录一次（token 存本机，长期有效，过期需重登）：

| 方式 | 操作 | 适合 |
|---|---|---|
| 一键登录 | DSH 设置 → **DeepSeek 网页版** → 「一键登录（打开 Edge）」，在弹出的窗口登录一次 | 首选，最省事 |
| 手工粘贴 | 浏览器 F12 → 网络 → 找 `/api/v0/chat/completion` 请求 → 复制 `Authorization: Bearer` 后的值 | 不方便弹窗口时 |
| 导入 | 把原 python 项目导出的 `credentials.json` 放到插件同级目录 | 迁移用户 |

**模型该做什么**：任何 `auth` 类报错（「尚未登录」「token 已过期」「HTTP 401/403」）出现时，
**先调 `deepseek_web_status`** 确认，再把状态和上面的登录指引原样转达用户，不要自己造地址或瞎猜。

---

## 常见错误排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 报「尚未登录」/ auth 错误 / HTTP 401/403 | 没登录或 token 过期 | 调 `status` 确认 → 引导用户去设置页重新登录（一键登录最快） |
| 报 PoW / WASM 错误 | 内置 `sha3_wasm_bg.wasm`（或 `.wasm.b64`）缺失，或 `wasmPath` 配置指向了不存在的文件 | 检查插件 assets 目录文件是否完整；改设置里的 `wasmPath` |
| 报「区间超限」 | 区间 > `maxLines`(400) 或 `maxChars`(60000) | 拆小区间；或让用户在设置里调大 `maxLines` / `maxChars` |
| 长时间无响应 / 报超时 | 网页端生成慢，或网络波动；单次超时默认 3 分钟 | 等待重试一次；仍慢就降低问题复杂度 |
| 返回内容是 HTML 而不是 JSON | 接口路径失效，或登录态被当成游客 | 通常是 token 过期 → 重新登录 |
| 报「并发/一路流冲突」类错误 | 有别的调用占用着唯一的流式通道 | **等上一个调用结束再发**，绝不并行 |

**通用原则**：报错后**先快照现状再行动**——`status` 检查和上一轮结果都在手边，别重复同样的失败调用。

## 账号安全与边界（务必遵守）

1. **全串行、单线程**：同一时刻只允许一路网页端流式请求。**绝不并发**发起多个
   `ask`/`analyze_lines`，也不要在 DSH 外绕过插件并行调用。
2. **不高频轰炸**：一次一问、串行推进，保持真人提问节奏。高频批量调用可能触发
   DeepSeek 风控，导致账号被限流、冻结甚至封禁。**后果由使用者自负。**
3. **只发必要内容**：发给网页端的内容会离开本机。敏感代码、密钥、私密数据**不要发**；
   长代码请用 `analyze_lines` 精确到行区间，而不是整文件糊上去。
4. **个人用途**：仅用于个人学习与自动化，遵守 DeepSeek 服务条款，不得用于违反条款的用途。

> 一句话：**当单线程用，别当 API 用。**

## 端到端示例（照这个节奏走）

场景：用户说「用 DeepSeek 网页版帮我看看 server.js 第 120–180 行的并发处理」。

1. 读取 `C:/proj/src/server.js` 确认行号与内容（自己先看，别瞎猜行号）。
2. 调 `status`（可选；如果之前没登录过，先确认登录态）。
3. 调 `analyze_lines({ path, start_line: 120, end_line: 180, focus: "并发", instruction: "重点：锁、竞态、共享状态；只列问题和行号" })`。
4. 拿到结果后，把**带行号的分析**直接呈现给用户，必要时引用原文行号说明。

场景：用户说「让 DeepSeek 给我要一份和刚才不同的答案」，且刚才答案来自本地模型。

1. 把本地模型的答案摘要放进 `prompt`。
2. 调 `ask({ prompt: "这是另一个模型给的答案，请你独立复核……", thinking: true })`。
3. 若用户接着追问，继续用同一 `label` 保持上下文。
